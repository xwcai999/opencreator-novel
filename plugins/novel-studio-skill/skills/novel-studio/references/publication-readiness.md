# 出版/投稿型项目就绪门禁

## 适用与原则

本门禁适用于所有用户明确要求出版/投稿的项目，并按 scope 缩放；目标篇幅为 5 万字以上时，必须执行完整三章试写、每 5—6 章投稿阶段、卷末与全本门禁；低于 5 万字者按短/中篇节奏合并阶段，但不免除投稿编辑盲审。它验证“读者会不会继续读、编辑能否看懂承诺”，不替代确定性校验，也不把字数、对白比例或分析分数当文学质量。

对已有普通 TXT/Markdown 或其他非 v2 稿件，默认执行只读审查：把现有前三章作为试读样本，不自动重写，也不直接创建状态或台账。项目级连续性校验只适用于符合 `project-schema.md` 的 v2 项目；若用户需要完整门禁，必须先取得授权，在新目录规范化正文、设定和状态。`migrate_project.py` 仅支持旧 `novel-planner` 项目，不是任意稿件导入器。

终章完成后的全本门禁必须另按 `fullbook-review.md` 执行，投稿 TXT 的文件完整性检查不能替代文学复评。阶段和全本均执行 `structure-similarity-review.md`；投稿编辑必须指出首次出现“下一章仍会用同一解法”的位置，而不是只评价节奏快慢。

门禁目标：

1. 在全书展开前，用前三章验证标题承诺、题材体验和外部目标。
2. 固定一名主笔，保持同一项目/卷的声音与决策记忆。
3. 用三类彼此隔离的盲审发现读者、连续性和投稿风险。
4. 失败直接路由到大纲、人物、场景或语言根因；同一根因层最多连续两轮，总计最多三次正文审查版本。第三版仍 BLOCK 时停止补丁式返修并上移根因。
5. 章节在局部回报完成后自然停笔，不用最低字数填充尾声。
6. 每个 5—6 章投稿阶段窗口必须兑现一次可复述的标题承诺变化或外部处境换挡；不把反复缺钱、倒计时、无后单或旁白表态当作阶段推进。

## 自动三章试写

不等全书写完，也不把门禁变成用户确认清单。主 Agent 读取现行权威资料后：

本节只适用于新建项目，或用户已明确授权在隔离副本中改写的项目。审查已有稿件时不得把本节当作写入授权。

1. 为第 1—3 章各生成控制卡，标出 reader_reward、active_pressure、human_cost、choice、memory_point、local_closure 和 carryover_debt。
2. 由固定主笔按顺序完成三章；相邻章节不并行写作。每章只做确定性自检，不在中途用审稿意见污染下一章。
3. 第三章完成后，对三章连续纯正文的同一最终版本并行启动三类盲审；通过后普通单章恢复两类盲审，出版/投稿编辑仅在每个 5—6 章投稿阶段窗口、卷末和全本终稿再次加入。
4. 主 Agent 合并为 PASS、定向返修或根因重构，不以“平均分”掩盖阻断问题。

三章通过的最低证据是：读者能说清标题承诺、主角外部目标、当前阻力、首笔个人代价和下一步原因；前三章各自有可复述回报；结尾有自然余波而非摘要或硬塞的新钩子。

后续每个 5—6 章窗口的投稿编辑盲审还必须写出：标题承诺在该窗口发生的一个不可逆或明显改变选择空间的行动后果，以及下一窗口的外部目标是否因此换挡。若只能复述“问题仍在、资源更少、期限更短”，按大纲或场景根因阻断后续续写。

## 标题承诺与外部目标

- 从标题抽取一个可观察的核心承诺（人物、独特条件、行动或收益）。
- 在第 1—3 章至少展示一次承诺如何改变人物行动；不能只在简介或旁白中宣告。
- 主角的外部目标、阻力和第一笔个人代价必须在前三章进入场景，并能推动下一章。
- 若标题承诺、外部目标、主驱动或结局需要重选，判为大纲层问题；只有这类重大方向变更才询问用户。

## 已接受阶段的跨章返修

- 阶段 BLOCK 先写入派生报告，不以候选大纲、候选正文或审稿意见更新权威状态。
- 跨章改动先在隔离候选目录完成；受影响 accepted 正文的旧审查哈希视为待替换，候选内容不得冒充现行事实。
- 从候选正文重建纯 TXT，完成三类隔离盲审与确定性校验。PASS 后才把候选正文写回权威目录，逐章重新绑定 body 哈希，并原子更新章节状态、当前状态、时间线、关系和待兑现台账。
- 候选版本仍 BLOCK 时，不得覆盖 accepted 正文，也不得用候选规划消除台账或状态错误。
- 标题是隐喻、氛围或终局型承诺时，以规范书名和读者契约中的核心体验/主线承诺为锚；不得为通过门禁强造反转、复购、事故或字面行动。

## 固定主笔

- 同一项目/卷默认使用同一正文写手、模型角色和文风约束。
- 返修仍交给原主笔，避免每轮换声音。
- 仅在主笔不可用、连续两轮语言层失败且证据指向声音不匹配，或用户明确改变文风时切换；记录切换原因和影响范围。
- 不把审稿代理临时变成写手，也不让相邻章节由不同写手并行创作。

## 三类隔离盲审

| 盲审 | 允许读取 | 禁止读取 | 主要问题 |
| --- | --- | --- | --- |
| 首次读者 | 当前正文、必要前章、读者画像 | 大纲、控制卡、作者解释、扫描和其他报告 | 是否想继续、是否困惑、每章回报和记忆点 |
| 连续性/文体 | 当前正文、必要前文、权威规则、只读扫描证据 | 首次读者和编辑报告、作者意图 | 事实因果、人物声音、说明密度、重复结构 |
| 出版/投稿编辑 | 标题、读者契约所需承诺、当前正文 | 其他两类报告、作者解释、预期缺陷 | 标题兑现、外部目标前置、赛程/任务可读性、结尾回报和投稿完整度 |

三类盲审使用独立上下文、独立输出；扫描只提供给连续性/文体审稿者。审稿意见不互相投票，由主 Agent 依据证据分类。

## 失败路由与轮次

| 根因层 | 典型证据 | 修订动作 | 同层上限 |
| --- | --- | --- | --- |
| 大纲 | 标题承诺或外部目标后置；层级/时间线难以复述；结尾不兑现 | 重排承诺、任务和阶段成果，必要时改纲 | 2 轮 |
| 人物 | 欲望、利益、声音相同；选择无放弃项；关系只服务主角 | 重建压力模型、合理反利益和人物决定 | 2 轮 |
| 场景 | 对战/流程重复；冲突无后果；章节只有记录没有回报 | 重排场景中心、失败余波和局部闭合 | 2 轮 |
| 语言 | 模板连接、说明腔、对白同质、总结拖尾 | 最小化改写句式与叙述距离，保留有效声音 | 2 轮 |

先按最早且最高层根因路由，不把大纲缺陷用语言润色遮住。某层连续两轮仍未清除阅读阻断，停止盲改并上移根因；若上移会改变标题、题材、核心关系、主要外部目标或结局，才向用户提出重大方向问题。普通质检不逐项等待用户确认。

## 自然篇幅与尾声

- word-count 是计划、校验和复盘证据，不是创作通过线。
- 场景已完成局部目标、人物选择和主要回报时立即收束；允许留下真实的关系、任务或代价余波。
- 禁止用重复战报、状态复盘、主题宣言、下一章预告或空泛环境段把章节补到最低字数。
- 若实际篇幅低于规划，优先调整章纲、章节数量或回报分布；不得在正文末尾加水段。

## 交付证据

至少保留：三章控制卡、三类盲审的独立结论、根因路由与轮次记录、最终正文哈希/确定性校验结果。证据统一写入 `报告/出版就绪/`：每个窗口分别保留 `首次读者.md`、`连续性文体.md`、`出版编辑.md` 与 `汇总.md`；`汇总.md` 必须写明审查范围、正文哈希、确定性校验结果、每层轮次、必修项、残余风险及结论。阶段窗口、卷末与终稿使用独立子目录，禁止覆盖旧证据。

当前没有单一脚本能够机器认证“出版就绪”。`analyze_publication_risk.py` 只输出只读风险候选，`record_chapter_review.py` 只绑定章节级接受证据；两者都不能替代三类盲审或单独给出出版 PASS。只有上述证据齐全、确定性错误为零且阅读阻断项清零时，主 Agent 才能在 `汇总.md` 记录人工/模型工作流结论，并仍须向用户说明这不是平台录用、法律、版权或商业结果保证。

只把必修问题和残余风险交付给主 Agent；不把审稿解释混入正文。

相关入口：planning-workflow.md 负责启动条件，reader-experience.md 负责回报与自然收束，chapter-workflow.md 负责写作、盲审和接受事务。
