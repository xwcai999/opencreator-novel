# 小说真实性修订

## 目标

把“去 AI 味”定义为修复真实读者能够感知的模板化、过度解释、人物同声和节奏同质，不判断文本来源，不优化任何 AI 检测分数。

保持三条边界：机器只找证据，审稿人结合语境裁决，固定写手做最小定向修订。禁止扫描器直接改正文。

## 两层证据

### 机器候选

运行：

```powershell
python scripts/scan_authenticity_artifacts.py --project-root <项目目录> --chapter <章节号> --json
```

- `workflow-leak`：写作说明、提示词角色标记或待办占位等疑似流程泄漏。回读确认不是有意元叙事后，按确定性硬错误处理。
- `contrast-template`、`negation-parade`：同章密集的反向定义或连续否定。
- `explanatory-bridge`、`abstract-cluster`：解释性连接和抽象概念聚集。
- `procedural-cluster`：同段流程词聚集，可能从场景滑向方案报告。
- `micro-action-density`、`simile-cluster`：可替换的微动作或比喻密集。
- `trailer-ending`、`verdict-ending`：预告片式或总结盖章式章末。

除确认后的 `workflow-leak` 外，所有命中都是第三层工艺证据。单个句式、破折号、排比、短句或某个词不能证明有问题。

需要在自动流程中阻断确定性泄漏时使用：

```powershell
python scripts/scan_authenticity_artifacts.py --project-root <项目目录> --chapter <章节号> --json --fail-on-blocking
```

脚本只读、无外部依赖，不给文学总分、不声称识别 AI，也不因普通复核候选返回失败。

### 人工语境裁决

连续性/文体审稿者读取扫描证据和必要上下文，逐项回答：

1. 叙述者是否复述了场景已经让读者看见的结论？
2. 隐去说话人标签后，主要人物能否凭词汇、句长、回避方式和利益立场区分？
3. 人物是否都完整、理性、正确地表达，缺少迟疑、遮掩、误判或不愿直说？
4. 抽象判断、流程和数据是否挤掉动作、物件、身体处境与关系变化？
5. 章末是否由场景挣得，而不是叙述者盖章或预告？
6. 与最近章节相比，事件结构、段落节奏、比喻和收尾是否再次同型？

每个确认问题标注 `outline`、`character`、`scene` 或 `language` 根因，并引用正文位置及读者影响。没有读者影响证据时保留为工艺警告。

## 章节闸门

1. 初稿完成作者型审查和项目校验后运行只读扫描。
2. 把扫描报告交给连续性/文体审稿者，不交给首次读者；首次读者不得被“找 AI 味”的预设污染。
3. 主 Agent 合并已确认的硬错误和阅读阻断项。普通扫描命中不自动进入返修清单。
4. 固定写手一次性完成定向修订；正文未改时不制造修订轮次。
5. 正文变化后，使用新上下文让首次读者盲读最终稿，只判断可预测、过度解释、人物被作者驱动和节奏失去变化的位置。
6. 必修项清零后沿用 `style-passed` 和 `rereview-passed` 记录接受证据，不增加第二套状态字段。

## 最小修订规则

按以下顺序选择改法：

1. 场景已经表达清楚时，删除重复解释，不补同义句。
2. 信息必须保留时，把结论落到人物选择、动作、物件、身体处境或带立场的对白中。
3. 人物说话过于完整时，恢复其身份允许的迟疑、回避、误判、沉默或不完整表达；不要统一改成短句口语。
4. 通用微动作没有人物功能时直接删除；有功能时改成该人物与当前处境独有的反应。
5. 章末总结没有新增功能时，停在最后一个有代价的动作、关系变化或具体画面上。

禁止全章洗稿、全局同义词替换、刻意错别字、随机句长、伪造口语噪声和为了“更像人”而新增未经设定支持的细节。保留人物特有的笨拙、方言、停顿、书面感和重复口头禅。

## 阶段复核

逐章扫描只定位局部候选；每 5—10 章继续运行 `analyze_prose_trends.py` 检查结构、说明密度和章末类型是否累积趋同。两类工具都只能把审稿人带回正文，不得以比例为目标反向调整文本。
