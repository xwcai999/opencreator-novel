# 逐章创作与接受工作流

## 写前最小读取

1. 读取 `作品.md`、`状态/当前状态.md`、目标章节细纲、最近一章和 `设定/读者契约.md`；`设定/文风档案.md` 仅在 `status: active` 时加入。
2. 运行待兑现审计，并把全部非终态项、到期项、冷线、禁止揭露项及章纲 `continuity-sources` 放在词项检索之前；再按人物、地点、关系和剧情线补充最小上下文。信息多时运行 `build_context_pack.py`，不得因预算截断连续性硬约束。
3. 如果细纲已可执行，直接提取章节控制卡；否则只补足缺失字段。
4. 检查本章不能提前改变的事实和当前阶段最容易重复的结构。
5. 按 `model-policy.md` 保持同一卷写手角色稳定；无法切换模型或隔离审稿上下文时明确降级，不伪造独立审稿证据。

出版/投稿型且目标篇幅 5 万字以上时，前 3 章先走自动试写门禁：固定同一主笔顺序完成三章，前三章通过标题承诺、外部目标、个人代价、章节回报和自然收束检查后，才展开后续章节。固定主笔覆盖同一卷或同一项目；只有模型不可用、声音稳定性已证实受损或用户明确要求改变，才换主笔并记录原因。字数只作计划与校验记录，不以最低值补写尾声。

## 章节控制卡

写正文前明确：

- `reader_reward`：本章给目标读者的可感知回报。
- `active_pressure`：正在挤压人物选择的具体压力。
- `human_cost`：事件会让谁付出什么个人代价。
- `counter_logic`：阻力方或不同立场为何合理。
- `choice`：人物必须作出的选择及放弃项。
- `memory_point`：读完后希望读者记住的画面、话语或变化。
- `local_closure`：本章内部完成了什么。
- `carryover_debt`：自然留给后续的情绪、关系、任务或信息债。
- `forbidden_pattern`：本章要避开的近期重复结构或句式。

控制卡是规划输入，不是第二套事实系统。可写入目标章节细纲或当轮工作记录，不要复制进权威状态。

## Subagent 快速严审调度

当用户要求正文交给 subagent，或多章任务适合代理协作且 subagent 可用时，采用以下职责边界：

- **主 Agent**：读取权威真值，提取控制卡与硬约束，调度代理，完成作者型审查，裁决审稿分歧，记录接受证据并提交状态；不承担正文初稿或大段正文返修。
- **固定写手**：一次只写当前章，并在交稿前自检 frontmatter、连续性硬约束、禁用结构和正文纯净度；正文返修仍交给该写手，避免声音漂移。字数不足但场景已闭合时调整章纲，不追加总结性尾段。
- **首次读者盲审**：只读取本章、必要前章和读者画像，独立判断开篇/回报、耐心、困惑和追读意愿；不读取大纲、控制卡、作者解释、真实性扫描、编辑意见或预期缺陷。
- **连续性/文体盲审**：读取必要前文、权威规则和只读真实性扫描证据，检查事实、因果、人物声音、说明密度和同型结构；不读取首次读者或编辑盲审结果，不修改正文。
- **出版/投稿编辑盲审**：只读取标题/读者契约所需的承诺信息与当前正文，按平台编辑视角检查标题兑现、外部目标前置、前三章留存、赛程/任务层级、章节回报、结尾回收和可投稿完整度；不读取其他两类审稿意见或作者解释。它只在前三章试写、每六章阶段窗口、卷末和全本终稿触发，不逐章重复。

前三章试写、阶段窗口、卷末和全本终稿由三类审稿者对同一正文版本并行工作，彼此隔离上下文与报告；普通单章沿用首次读者与连续性/文体两类盲审。主 Agent 把硬错误和阅读阻断合并成一次返修任务，不逐条启动微修订。工艺警告默认记入报告；只有跨类型、影响追读或兑现的证据才进入本轮必修。

不得让多个写手并行撰写相邻章节。审稿期间可以预构建下一章上下文包和控制卡，但当前章 `accepted` 前不得开始下一章正文。

审稿者意见不是投票。出现分歧时，主 Agent 按“现行正文与权威状态 → 设定 → 已确认大纲 → 本轮计划 → 历史报告”的证据顺序裁决；误读规则不自动触发返修。事实正确但表达可能引起目标读者误解时，只有达到阅读阻断标准才返修，否则记录为工艺警告。

## 初稿

- 遵循 POV、时态和人物语言档案。
- 让压力通过行动、环境反馈、利益差异和回避方式进入场景。
- 让流程和数据改变人物处境；不要把解决方案本身当作高潮。
- 保持题材承诺；不为制造钩子临时增加秘密、误会、事故或反派。
- 只把小说正文写进章节正文区。分析、TODO、控制卡和审稿意见放入报告或工作区。

## 写后接受闭环

按顺序执行，不得在通过前更新权威状态：

1. **作者型审查与确定性校验**：核对连续性、人物动机、选择、代价、题材兑现和控制卡；校验失败必须先修复。随后按 `authenticity-revision.md` 运行只读真实性扫描。
2. **隔离盲审**：普通单章由首次读者与连续性/文体审稿者评估；前三章试写、每六章阶段窗口、卷末和全本终稿再加入出版/投稿编辑。真实性扫描只提供给连续性/文体审稿者，编辑盲审只得到标题/读者契约所需承诺，不得到其他报告。
3. **主 Agent 裁决**：区分硬错误、阅读阻断、工艺警告和误判；普通扫描命中不自动升级，只汇总前两类必修项。
4. **集中定向修订**：存在必修项时，一次性交给固定写手修复，保留有效段落和人物声音。
5. **必要时独立复审**：正文 body 发生变化后，使用全新上下文重新读取最终正文，确认必修项消失且未产生新矛盾；真实性修订后的首次读者仍不得看到扫描命中项。正文未变化时，步骤2中已独立审查最终正文的对应审稿者可作为复审证据，不因形式完整性重复启动盲审。
6. **接受证据**：硬门禁通过且阅读阻断项清零后，运行 `record_chapter_review.py`，把审查结论与最终正文 body 哈希绑定。
7. **提交状态**：接受证据有效后，才设置章节为 `accepted`、提交状态差异并重建索引；最终再次运行 `validate_project.py`。

同一根因层最多两轮，四层按大纲 → 人物 → 场景 → 语言自动路由：承诺、外部目标、赛制层级或结尾方向缺失归大纲；欲望、利益、声音或选择不成立归人物；重复节拍、无后果冲突或回报未落地归场景；说明腔、模板句、对白同质或收束拖尾归语言。两轮仍失败就停止该层盲改并上移根因；只有需要改变标题承诺、题材、主要外部目标、核心关系或结局等重大方向时才询问用户。常规质检不把用户当作逐项确认依赖。

短篇 `light` 可在一次输出中完成控制卡、适用的审查和定向修订，不强制落多份报告；独立读者上下文和“先接受后提交”仍须保留。出版/投稿型 5 万字以上项目不适用该合并例外，必须在前三章、阶段窗口、卷末和全本终稿完成三类隔离盲审。

## 状态事务

1. 初稿后只生成候选状态差异。
2. 运行 `validate_project.py`；确定性错误必须修复。
3. 把审查证据写入 `报告/章节审查/` 或当前工作输出，绝不插入正文。
4. v2 项目使用 `record_chapter_review.py` 固定审查证据；它不修改正文和状态。
5. 阅读接受后，才更新人物、时间线、关系、待兑现项和当前状态。
   - 新线索首次进入正文用 `planted`；旧线索再次出现用 `reinforced`；只解释一层用 `partial`；持续代价/规则用 `active`；最终真相或完整承诺才用 `fulfilled`。
   - 同步更新最近推进章节、正文证据、兑现窗口与禁止提前揭露内容。不得仅因本章完成阶段任务就关闭长线项。
6. 更新章节 `status` 与 `word-count`，运行 `validate_project.py` 和 `reindex_project.py`。校验器会核对连续 accepted 边界、报告和正文哈希。

用户可以明确覆盖阅读接受门禁，但必须记录覆盖理由和仍存在的风险；用户覆盖不能跳过确定性硬门禁。除标题承诺、题材、主要外部目标、核心关系或结局等重大方向外，不把用户当作常规质检、逐条确认或轮次推进的依赖。
