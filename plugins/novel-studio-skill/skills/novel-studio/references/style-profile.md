# 文风档案规则

## 定位

`设定/文风档案.md` 保存本书校准通过的表达偏好，用于减少跨章声音漂移。它不保存剧情事实，不替代人物档案、读者契约或章节细纲。

## 激活

- `status: inactive`：模板、草案或待确认内容；不得进入正文上下文。
- `status: active`：已通过模型盲评或用户明确覆盖；写手和文体审稿者必须读取。
- 文件缺失：视同 inactive，旧项目完全沿用当前流程。

## 可用证据

只从以下来源提炼：

1. 同场景 A/B/C 样稿的隔离模型盲评胜者。
2. 用户直接描述的偏好与禁忌。
3. 用户拥有或提供的自有样稿。
4. 用户明确认可的 accepted 章节。
5. `analyze_prose_trends.py` 定位后回读确认的具体段落。

不要把未接受草稿、单次模型偶然输出、统计比例或某位作者姓名直接固化为规则。只记录叙事距离、句法节奏、对白方式、感官偏好、心理呈现和禁用表达等可观察特征。

## 更新流程

1. 新书优先按 `style-calibration.md` 生成同场景匿名候选；已有样稿则生成候选差异，标明证据章节和具体段落。
2. 区分稳定偏好、人物专属声音和本章特殊效果。
3. 仅把稳定偏好写入项目文风档案；人物专属内容留在角色文件。
4. 经隔离模型盲评或用户明确覆盖后更新内容和 `last-confirmed-chapter`，再设置或保持 `status: active`。
5. 文风档案更新只影响后续候选；未经授权不回改 accepted 正文。

初次激活和重新校准都使用 `activate_style_profile.py`。模型盲评路径提供机器可读评审证据，不要求用户确认；旧人工路径继续要求 `--user-confirmed`。脚本始终默认只预览，正式写入必须携带预览返回的当前档案哈希和 `--apply`，避免覆盖同时发生的修改。

## 使用边界

- 把档案当作倾向和禁区，不把句长、对白比例或修辞数量变成硬指标。
- 文风与事实冲突时，以正文事实和权威状态为准。
- 文风与读者契约冲突时，先报告冲突，不擅自牺牲核心读者回报。
- 不要求模型逐条展示遵循过程；审稿只引用产生实际读者影响的偏差。
